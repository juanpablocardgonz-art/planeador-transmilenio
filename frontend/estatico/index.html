Bajo el capó — R5 Planear un viaje

Grafo estación ↔ ruta. Dos barridos (motor/planificador.py): hacia atrás desde el destino anotando cada posible transbordo, y hacia adelante desde el origen buscando el destino o una estación anotada. Arreglos indexados por id con marcas de versión para no reiniciarlos.

Complejidad: O(Lorigen + Ldestino), L = largo de las rutas que pasan por ahí.

Bajo el capó — R4 Próximo bus

Hash (ruta → parada) y búsqueda binaria (lower bound) sobre el arreglo de horas de esa parada, que se ordenó con Merge Sort al cargar (motor/ordenamiento.py).

Complejidad: O(log h), h = buses de esa ruta en esa estación.

Escribe el nombre de una estación, por ejemplo CALLE 26.

Bajo el capó — R1 Buscar una estación

Tabla hash propia con encadenamiento (motor/tabla_hash.py): nombre → estación. Función hash polinomial, rehash al superar factor de carga 0.75.

Complejidad: O(1) promedio. Alternativa descartada: búsqueda binaria O(log n).

Bajo el capó — R2 y R3

Árbol AVL con los nombres de las estaciones abiertas (motor/avl.py). El recorrido en orden empieza en el primer nombre ≥ desde y se detiene al pasar hasta. Las cerradas nunca aparecen.

Complejidad: O(log n + r), r = estaciones devueltas.

Bajo el capó — R6 Ranking

AVL con clave (-buses, nombre): al negar los buses, el recorrido en orden da primero las de más buses y desempata alfabéticamente. Solo se actualiza cuando algo cambia (cerrar, reabrir, editar una ruta).

Consulta: O(log n + k). Alternativa descartada: ordenar todo en cada consulta, O(n log n).

  1. Elige una ruta para ver su recorrido.

Bajo el capó — R7, R8 y R9

R7. Cada ruta es una lista doblemente enlazada de paradas + una tabla hash estación → nodo (motor/lista_doble.py). Insertar o quitar es O(1) (+ O(log n) para actualizar el ranking).

R8. Cerrar saca la estación de los dos AVL (nombres y ranking); reabrir la vuelve a meter: O(log n). El planificador de viajes salta las estaciones cerradas.

R9. Patrón Command con dos pilas (motor/historial.py). Un truco de la lista enlazada hace que deshacer una parada sea O(1): al desenlazar un nodo no se borran sus punteros.

Bajo el capó — R10 Fila de abordaje

Cola FIFO sobre arreglo con índice de frente (motor/pila_cola.py, motor/simulacion.py). Por cada bus: entran a la cola los que ya llegaron y suben hasta llenar la capacidad.

Complejidad: O(P + B), P = pasajeros, B = buses. Con list.pop(0) sería O(P²).

R11 Panel de rendimiento

Igual que el script del profesor: cada operación se mide en redes generadas de 10.000, 20.000, 40.000 y 80.000 estaciones (mediana de varias repeticiones). Si el tiempo crece como dice la complejidad esperada, la decisión fue correcta. R5 (planear un viaje) se muestra, pero el profesor no lo mide: no depende de n, sino del largo de las rutas que pasan por el origen y el destino.
